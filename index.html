Fixed weights, growing cache

Part 4 · Questions

The questions that make it click

The points that usually stay fuzzy after reading the formula. Tap one to open it.

Attention outputs one vector per token. So where does the next token actually come from?

Attention never picks a token. It only updates vectors: three tokens in, three vectors out. The next token comes at the very end, after all the layers. The last vector is multiplied by an output matrix with one column per vocabulary entry, giving a score for every possible token. Softmax turns those scores into probabilities, and one token is picked. Stages 9 and 10.

Why is only the last position used for the prediction?

Every position is trained to predict the token right after it. “I” predicts “am”, “am” predicts “Nipun”. When generating, you already know those answers, so the only new prediction is from the last position. Thanks to attention, that last vector isn't just about “Nipun”: it has absorbed the whole sentence. Stage 9.

Why don't the attention scores match the attention matrix?

The attention matrix is the scores after softmax, applied row by row: softmax(zᵢ) = ezᵢ ÷ Σ ezⱼ. The numbers change completely, but the ranking is kept. A higher score always gets a bigger share, and every row adds up to 100%. Only differences between scores matter, so 0.23 versus −0.13 becomes 59% versus 41%. Stages 4 and 5.

What does the attention output actually mean, after W_O and the residual?

It's the same token, updated with context. Z is a blend of the value vectors of the tokens it attended to. W_O maps that blend back into the model's main vector space. Adding the original X back (the residual) means attention adds information rather than replacing the token. After the step, each row means “this token, in the light of what came before it.” Stage 6, step ④.

Where does the feed-forward fit, and why does it need a nonlinearity?

Every layer is attention followed by a feed-forward network. Attention moves information between tokens; the feed-forward then processes each token on its own: expand, bend, shrink. The bend (ReLU, GELU or SwiGLU) matters because matrix multiplications chained together collapse into a single matrix multiplication. Without a nonlinearity, 64 layers would be no more expressive than one. Stage 7.

Is W_Q shared across layers, while only K and V differ?

No. Every layer has its own W_Q, W_K, W_V, W_O and feed-forward weights. Nothing is shared. The real asymmetry is at runtime, between the vectors: each token's key and value are kept in the KV cache because every later token needs them, while a query is used once and thrown away. Part 2.

Are the weights loaded every time a token is generated?

No. All the weights are loaded into GPU memory once, at startup, and stay there. Every step reads them again (which is why inference is often limited by memory bandwidth), but they never change. What grows is the KV cache, by one key and one value per layer for each new token. Part 2.

In a 140B model, where do the parameters actually go?

Mostly into the feed-forward layers, about 72%. With a hidden size of 12,288 and 64 layers, W_Q, W_K, W_V and W_O each total about 19 GB in fp16, while the feed-forward totals about 203 GB. On top of that, the KV cache costs about 3 MB per token without grouped-query attention, so a 128k-token context needs more memory than the model itself. Part 3.
